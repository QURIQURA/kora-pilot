# SHCS 몰드 시스템 1차 수정 보고

## 구현
- 공용 숫자 치수/면적/단위 변환 함수를 추가했다.
- 새 몰드 생성 시 내부 치수를 숫자 필드로 저장한다.
- Inventory의 입력·표시를 cm, 저장을 mm로 통일했다.
- 몰드 선택 변경/해제 시 이전 치수·몰드 개수 잔류를 제거했다.
- NULL 치수는 빈칸과 안내로 표시한다. 이름 문자열에서 실측 치수를 추측하지 않는다.
- 원형은 지름, 사각은 가로×세로로 외곽 면적을 계산한다.
- Settings에 6개 참고 규격과 측정 안내/크림 초기 목표표를 추가했다.
- 8인치 샌딩800g은 읽기 전용 사용자 지정 초기 목표다. 기존 제품 구성에 자동 적용하지 않았다.

## DB
스키마 변경 없음. 신규 [참고] 몰드 6행 추가와 기존 트리거의 capacities 미러 6행 생성만 실행했다.
신규 데이터에는 생성 배치 표식, 출처, 실측 전 상태를 NOTES에 남겼다. reference_weight_g는 NULL이다.
기존 moulds 5행 전체가 변경 전 값과 동일하다.
orders 16개와 work_sessions 11개, cake_sizes, product_sizes, product_components 전체 JSON 집계 해시가 전후 동일하다.
기존 Cacao 오더와 자동 매핑하지 않았다.

변경 전 백업·신규 행 목록·검증 결과·적용 SQL·롤백 SQL은 별도 비공개 백업 파일에 보관한다.

롤백 SQL은 실행하지 않았다. 정확히 이 배치의 6행인지 확인하고,
생성 후 편집되거나 moulds/capacities를 참조하는 레코드가 생겼으면 중단한다.
삭제에 앞서 모든 외래키 참조를 확인하며 기존 몰드와 오더·세션의 연결을 바꾸지 않는다.

## 검증
- npm run test:mould: 6개 통과.
- npx tsc --noEmit: 통과.
- 변경한 TS/TSX 파일 ESLint: 오류 0. Inventory useMemo 의존성 기존 경고 1개.
- npm run build: 통과.
- git diff --check: 통과.
- DB 사후 조회: 참고 몰드 6개, 높이100mm, 미측정 반죽량NULL, capacities의 지름/높이 미러 일치.
- 원형 외곽 면적 176.71/314.16/490.87cm², 정사각225/400/625cm² 확인.
- 브라우저 자동화용 Chromium 다운로드가 실패해 브라우저 클릭/저장 통합 테스트는 수행하지 못했다.
  운영 DB에 테스트 오더·생산 세션을 생성하지 않았다.

단위/데이터 회귀 테스트를 브라우저 전체 통합 테스트로 간주하지 않는다.
Mould→Inventory는 공용 매핑 로직 수준에서 검증했으며,
Cake Size→Product Size→Order→Session→원가/재고 전체 흐름은 후속 통합 단계다.

## 남은 결정
기존 Cake Size의 8인치 지름250mm, 중복 이름/NULL, Product Size 지름200mm와의 불일치는 여전히 존재한다.
완성 치수와 도구 치수는 별개이므로 신규 20cm 몰드를 추가했다고 Cake Size를20cm로 자동 변경하지 않는다.
기존 Rectangle 27×32×3 등 숫자가 NULL인 몰드는 실측값 확인 후 명시적으로 보완해야 한다.
