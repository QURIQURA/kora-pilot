# 컴포넌트 생산 리스트

PRODUCTION 대시보드에서 WANN Planner의 Project → Task 계층과 같은 방식으로 컴포넌트를
부모 행, 날짜별 생산 블록을 하위 행으로 표시한다.

- 부모 행에 컴포넌트 이름/버전, 주문별 배정, 배수/총중량과 MERGE를 함께 표시한다.
- 부모 행을 펼치면 주문별 생산 단계를 볼 수 있다. 단계도 펼쳐야 실제 시간/타이머,
  작업시간/생산량/관찰/체크리스트/단계 메모를 입력할 수 있다.
- 타임라인에서 블록을 선택하면 해당 컴포넌트와 생산 단계가 열린다.
- 분할 블록은 같은 컴포넌트의 하위 단계로 표시한다. 수량을 중복 집계하지 않는다.
- 기존 TASK DETAILS 독립 상자와 ADJUST QUANTITY 독립 상자를 이 계층으로 통합했다.
- 세션의 구성 추가/제거와 세션 전체 메모는 별도 접힌 관리 영역으로 옮겼다.
  단계 메모는 기존 work_session_tasks.note, 세션 메모는 기존 work_sessions.notes에 저장한다.
- 관리 영역과 생산 단계는 펼칠 때만 mount한다. 접힌 기록 때문에 TASK를 생성하지 않는다.
- 변경 이력은 컴포넌트 아래에서 필요할 때만 조회한다. 기존 데이터/연결은 이동하거나 삭제하지 않는다.

## MERGE 배수 저장 후 화면 지연 수정

DB에서는 ×4가 저장됐어도 모든 세션/대시보드/블록 쿼리 invalidation을 기다리는 동안
기존 ×2가 남아 보일 수 있었다. 확인한 사례는 두 선택 행의 DB 값이 각각 ×2로, 합계 ×4였다.

저장 응답에 id/multiplier/updated_at을 받아 정확히 변경한 선택의 캐시와 대시보드 캐시에
함께 반영한다. 진행 중인 이전 조회는 취소하고, 전체 background refetch를 기다리지 않고
저장을 종료한다. 변경 이력 실패는 수량 저장과 구분해 알린다. 저장 중 표시도 제공한다.

## 검증

- TypeScript 검사, 프로덕션 빌드.
- 31개 시스템 테스트. 추가 회귀 테스트는 MERGE한 두 ×1을 합계 ×4로 저장했을 때
  수량 행/계량 데이터가 즉시 ×4, 342.5g 기준 1370g이 되는지 확인한다.
- WANN Planner MultipleTasksPanel의 펼침 상태·부모/들여쓰기된 자식 구조를 참조했다.
- 로그인한 실제 브라우저에서의 화면 검증은 수행하지 못했다.
