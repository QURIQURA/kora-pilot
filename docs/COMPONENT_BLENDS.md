# 컴포넌트 조합

COMPONENTS → COMBINE COMPONENTS에서 원본 Formula Version과 사용할 g을 선택한다.
이름을 입력하고 생성하면 새 Component, Formula, DRAFT V1을 한 트랜잭션으로 만든다.

- 원본 버전, 혼합 중량, 원재료, 제조 메모를 생성 당시 스냅샷으로 보관한다.
- 원재료를 g으로 환산해 같은 재료 ID끼리 합산한다. 기존 원가·생산량 계산에서 그대로 사용한다.
- 원본에 g/kg 외 단위가 있으면 모호한 중량을 추정하지 않고 생성을 중단한다.
- 새 조합을 다음 조합의 원본으로 사용할 수 있다. 기존 조합을 수정하거나 순환 연결하지 않는다.
- 원본 변경은 자동 전파하지 않는다. 새 버전을 명시적으로 선택해 새 조합을 만든다.
- 생성 당시 COMPONENT MIX는 기록이다. 생성된 원재료를 수동 변경하면 이 기록과 달라질 수 있다.
- 혼합 g은 원재료 합산 중량 기준이며 조리/수분 손실이나 실제 수율은 추정하지 않는다.
- 모든 조회/생성은 user_id로 제한한다. RPC는 SECURITY INVOKER이며 익명 실행은 금지한다.

## 검증

- `npx tsc --noEmit`
- `npm run test:system`: 원재료 병합, kg 환산, 기본 배합의 중량 보존, 잘못된 단위/수량 차단.
- `npm run build`
- 운영 DB에서 authenticated 역할로 생성 후 총량·원재료·소스 버전을 재조회했다.
- 롤백 트랜잭션으로 음수 중량, 중복 버전, 다른 사용자 원본 차단 및 부분 생성 없음 확인.
- 익명 실행 권한 없음 확인. 신규 함수에 대한 보안 Advisor 지적 없음.

## 되돌리기

먼저 UI 커밋을 revert한다. 생성한 레시피를 사용 중일 수 있으므로 데이터는 자동 삭제하지 않는다.
DB 필드는 기존 버전에서 빈 배열이므로 남겨 두어도 기존 동작에 영향이 없다.
기능 자체를 제거하려면 사용 의존성을 확인한 후 RPC와 component_sources 제약/필드를 제거한다.
배합 데이터 취소는 해당 사용자 소유의 새 DRAFT/새 Component만 대상으로 별도 검토한다.
기존 가나슈 V1, 주문, 생산 세션, 재료 원장은 변경하지 않는다.
